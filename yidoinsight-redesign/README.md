## 1. 원본 사이트 분석 요약

**정체성:** 서울이도치과 공식 홈페이지(seoulyido.com)와 따로 운영하는 콘텐츠·저널 사이트입니다. 치아백과, 증상 찾기, 원장 칼럼, 상담 준비 글이 중심이고 KR/EN/JA/ZH 4개 언어를 지원합니다.

**현재 디자인 토큰**

| 역할 | 값 |
|---|---|
| 배경 | `#FFFCF3` 미색, 보조 `#EEE8DD` |
| 다크 섹션 | `#302E29` 차콜 |
| 포인트 | `#E95E27` 오렌지, 텍스트용 `#A23D17` |
| 서체 | DoctorInsight Sans / Noto Sans KR, 로고만 Georgia 세리프 |
| 형태 | radius 2px, 그림자 없음, 얇은 구분선, 아웃라인 버튼 |

**메인 섹션 13개 (PC 기준 세로 약 11,000px)**
상단 띠 → 헤더(메뉴 7개) → 히어로 + 브랜드 영상 → 사이트 소개 + 많이 찾는 질문 → 방문 전 안내(진료시간 접힘) → 질문 검색 → 치아백과/증상 진입 카드 → 의료진 단체 사진 + 칼럼 3 → 상황별 상담 카드 6 → 의료진 3 + 교정 원장 → 콘텐츠 작성 기준 → 오렌지 예약 유도 섹션 → FAQ 6 + 지역 문단 → 푸터

**개선이 필요한 점**

1. **같은 링크가 반복됩니다.** 방문 안내 링크가 10번 넘게, 임플란트 상담 글 링크가 5번 나옵니다. "상담을 준비해 보세요"라는 문구도 섹션마다 되풀이됩니다.
2. **첫 화면에서 할 수 있는 일이 없습니다.** 영상이 화면을 다 차지하고, 예약·검색·진료시간이 보이지 않습니다.
3. **카드 이미지 스타일이 섞여 있습니다.** 실사 사진과 글자가 들어간 AI 일러스트가 섞여 있고, 교정 카드는 이미지가 비어 있습니다.
4. **하단 FAQ·지역 문단의 톤이 다릅니다.** 회색 박스에 다른 서체를 써서 SEO용으로 덧붙인 것처럼 보입니다.
5. **가장 많이 찾는 정보가 숨어 있습니다.** 진료시간이 접혀 있어 한 번 더 눌러야 보입니다.

## 3. A안 · Clinical Index (`A-clinical-index/`)

### 콘셉트
치과 차트와 백과사전 색인을 닮은 정보 중심 디자인입니다. 모든 용어에 진료 영역 코드(`IM-01`, `PR-02` 등)를 붙여 문서처럼 정돈된 인상을 주고, 치과 차트의 표기 관례를 색에 그대로 가져왔습니다. **빨강 = 확인이 필요한 부위**, **파랑 = 링크·기존 정보**입니다.

### 섹션 구성

|---|---|---|---|
| 0 | 상단 띠 · 헤더(sticky) | 로고(YIDO 4칸 마크), 메뉴 5개, 진료시간·네이버 예약 버튼 | 메뉴 7개를 5개로 줄임. 칼럼과 상담 준비 글을 하나로 합침 |
| 1 | 히어로 | 큰 검색창(실시간 결과), 자주 찾는 말 칩, 오른쪽에 **오늘 진료 상태 카드** | 영상 대신 검색. 진료시간을 펼친 상태로 첫 화면에 노출 |

- **검색:** 용어 20개와 글 8편을 대상으로, 입력하는 즉시 상위 5건을 보여주고 검색어를 하이라이트합니다.
- **오늘 진료 상태:** 한국 시간 기준으로 "지금 진료 중 · 18:30까지", "점심시간", "오늘 진료가 끝났습니다 · 다음 진료 ○요일"을 자동 표시하고, 오늘 요일 줄을 강조합니다. 공휴일은 판단하지 않으므로 실제 개발 때 공휴일 API나 수동 휴진일 데이터를 연결해야 합니다.
- **FDI 차트:** 앞니(x1–x3), 작은어금니(x4–x5), 큰어금니(x6–x7), 사랑니(x8)와 잇몸·턱관절 버튼이 있습니다. 증상 문구의 관련 용어 칩을 누르면 아래 색인의 해당 줄이 잠깐 강조됩니다.
- **전화번호 복사 버튼:** `tel:` 링크가 동작하지 않는 환경에 대비해 넣었습니다.

## 5. C안 · 상담 노트 (`C-consult-note/`)

### 콘셉트
"진료실에서 할 말, 미리 적어 가세요." 방문자가 직접 쓰는 도구입니다. 3단계로 고르면 오른쪽(모바일에서는 아래)에 줄 노트 한 장이 실시간으로 완성되고, 진료 때 이 화면을 의료진에게 보여주면 됩니다. 노란 형광펜은 "선택됨" 상태에만 씁니다.

### 화면 구성

| 영역 | 내용 |
|---|---|
| 앱 바 | 서비스명, 치아백과·진료시간, 예약 버튼 |
| 소개 | 제목, 3단계 안내, "예시로 채워 둔 노트" 배너 |
| STEP 1 · 고민 고르기 | 임플란트 / 보철·크라운 / 교정 / 잇몸 / 시림·통증 / 첫 방문·검진 (여러 개 선택 가능) |
| STEP 2 · 상태 적기 | 부위(입 모양 6칸, FDI 사분면 1x–4x 표기), 시작 시기, 불편한 상황, 불편 정도 0–10, 의료진이 알아야 할 것 |
| STEP 3 · 질문 고르기 | 고른 주제별 질문 체크리스트, 직접 질문 추가 |
| 내 상담 노트 | 날짜, 주제, 부위, 시작, 상황, 정도 막대, 알릴 것, 물어볼 것(Q1, Q2…), 메모 |
| 노트 버튼 | 노트 내용 복사(네이버 예약 요청사항에 붙여넣기 용), 네이버 예약, 처음부터 쓰기 |
| 보조 카드 | 고른 주제에 맞는 읽을거리, 진료 안내 |
| 모바일 하단 바 | 작성하기 / 내 노트(질문 개수 배지) / 예약하기 |

### 동작 방식
- 처음 열면 예시 데이터(임플란트, 왼쪽 아래, 한 달 이상, 질문 3개)가 채워진 상태로 보입니다. 무엇이든 바꾸면 예시 배너가 사라집니다.
- 입력 내용은 브라우저 `localStorage`(키 `yido-consult-note-v1`)에만 저장되고 서버로 보내지 않습니다. 개인 건강정보이므로 실제 서비스에서도 서버 저장 없이 이 방식을 유지하는 것을 권합니다.
- 질문 문구는 원본의 상담 준비 글 내용을 바탕으로 시안용으로 작성했습니다. 실제 반영 전에 의료진 감수가 필요합니다.

## 6. 공통 사항

### 반응형
- 데스크톱 1440px, 모바일 390px에서 가로 스크롤 없이 확인했습니다. 단, B안은 모바일 측정값이 1px 넘어서 `overflow-x: clip`으로 가렸습니다.
- 모든 시안이 시스템 다크 모드를 따릅니다(`prefers-color-scheme`). `<html data-theme="light|dark">`로 강제할 수도 있습니다.
- 노치·홈 인디케이터 영역(safe-area)을 고려했습니다.

### 콘텐츠 출처

### 개발로 옮길 때
- 각 시안의 데이터는 `<script>` 맨 위의 배열(`TERMS`, `COLUMNS`, `GUIDES`, `FAQ`, `ZONES`, `TOPICS`)에 모여 있습니다. CMS나 JSON으로 그대로 옮기면 됩니다.
- 용어 코드 규칙은 `SY` 증상·통증, `DX` 검사·진단, `EN` 보존·신경치료, `PR` 보철·수복, `IM` 임플란트·발치, `PE` 잇몸·예방, `OR` 교정·성장, `TM` 턱관절·구강외과, `IN` 보험·비용입니다.

- 색은 모두 `:root`의 CSS 변수로만 지정했습니다. 사내 `setting.css` 유틸리티로 옮길 때는 이 변수를 토큰으로 매핑하면 됩니다.
